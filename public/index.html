Settings

Devices

↕ The Handy

With an Application ID the player uses the new Handy API v3: the Handy stays in sync even at other playback speeds (0.5× … 2×). Without an ID as before (API v2, 1× only). An Application ID is not a secret – the player doesn’t need the secret Application Key.

Without internet: Handy via Bluetooth

Switch the Handy to Bluetooth mode and connect it with Intiface Central (phone or PC). Then connect under “Satisfyer → Intiface Central”. The player recognises the Handy as “↕ movement” and drives it directly – without the Handy cloud. Stroke, invert, offset, patterns, direct control and finale work as usual.

Anything faster is too much for the motor – the script intensity adapts such spots. The player detects the model when connecting. There are no measured values for Handy 2 / 2 Pro yet – if yours manages more, turn automatic off and raise it.

Connect, offset and stroke are set while watching in the devices panel. Touch pad: Tempo = finger height is the stroke tempo, Position 🧪 = the Handy follows your finger (beta).

〰 Satisfyer

Several Satisfyers at once: in the device column (tap the status at the top) simply “＋ Connect another Satisfyer”. Each gets its own strength and lead – so all stay in time together.

Translation script → vibration

Smooths the vibration over time: 0 = every stroke felt on its own, higher = calmer, fluctuates less. For fully even: “By speed” plus smoothness 40–60 %.

Intiface Central (also: Handy via Bluetooth)

Start Intiface Central on the phone, enable “Listen on all interfaces” in its settings and start the server.

Fixed via INTIFACE_LAN_ONLY in docker-compose.yml.

Emergency stop & privacy

The Esc key, the red STOP button or “Stop all” in the device column stop everything immediately. The auto-stop applies to direct control, patterns, “control it yourself” and manual strength – a playing video with a script counts as “watching”. “Maximum” of the Satisfyer limits the vibration.

For showing the player to others. Applies only to this device. Without the switch: open the address with /demo at the end (e.g. as a link for someone else).

Script

🎚 Script intensity

Default for all scenes

  • Original – exactly the file, nothing changed.
  • Automatic – stretches scripts with a small stroke to the full range; what the Handy can’t manage is adapted so it stays exactly in time (fine vibrations stay).
  • Gentle – stroke 20–80 %, at most 240 %/s, Satisfyer weaker and smoother.
  • Intense – full stroke, calm passages at double or triple tempo, Satisfyer stronger.

Applies to Handy and Satisfyer together and only recalculates during playback – your files stay unchanged. Per scene you choose in the script area at the video; it is remembered like the offset.

🎯 Calibrate the offset by tapping the beat: in the device column under “Offset fine-tuning” or key T while the video plays.

🔥 Finale

The 🔥 button in the player (or key O) switches to calmer. Press again = back to normal video sync.

      VR & HereSphere

      Then the player’s normal address is enough in HereSphere. HereSphere is recognised by its identifier; only the start page is redirected.

      Open this address in HereSphere’s browser and bookmark it:

      ⓘ How it works
      1. Start HereSphere → open the web browser → enter the address above.
      2. The library appears with categories: Alle mit Script (all with script), your saved Stash filters and the mounted folders.
      3. The Handy: enter your connection key in HereSphere under Settings → Haptics. HereSphere loads the Funscript automatically.
      4. The player detects the VR format (180°/360°, SBS/TB, fisheye/MKX) from file names and VR tags.

      If your reverse proxy has a login (e.g. Authelia) in front of the player, /heresphere must be exempt – HereSphere can’t handle a login page. The password above still protects the interface.

      System

      ⬆ Update available What's new? ↗

      Update: docker compose pull && docker compose up -d – your settings live in the volume funscript-data and stay.

      Everything the player stores (settings, own scripts, offsets, patterns) lives on the server in the Docker volume funscript-data – backing it up backs up everything. At startup the player checks itself; the result is in docker logs.
