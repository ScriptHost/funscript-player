Wie der Funscript Player gebaut ist

Ein Node.js-Server ohne Abhängigkeiten und eine statische Oberfläche aus einfachen Skripten – kein Build-Schritt, kein Framework. Alles, was die Geräte steuert, läuft im Browser.

Aufbau

Der Server liefert die Oberfläche aus, streamt Videos, reicht Stash durch und vermittelt die Fernbedienung. Handy (Cloud) und Satisfyer (Bluetooth) spricht der Browser direkt an.

Dateien

Die Skripte in public/ sind klassische <script>-Dateien ohne Module. Sie teilen sich globale Funktionen und werden in dieser Reihenfolge geladen – spätere dürfen frühere benutzen, umgekehrt nur zur Laufzeit (mit typeof x === 'function' absichern).

Kernkonzepte

Zeitachse

mediaTime(), seekTo(), duration() und videoPlaying() sind die einzige Wahrheit über das Video. Sie berücksichtigen den HQ-Stream (startet nach jedem Spulen bei 0 → hq.offset) und die Fernbedienung (Zeit kommt vom Bildschirm). Nie direkt video.currentTime oder video.paused für Gerätelogik verwenden.

Wer steuert die Handy?

handy.owner ist 'video', 'manual', 'pattern', 'sequence' oder 'finale'. claimHandy(owner) wechselt und sendet das Event handy-owner – die anderen Bereiche setzen sich darauf zurück (z. B. pausiert das Video).

Script-Kette

script.actions → toolActions() (Script-Werkzeuge) → sendActions() (Finale „halbes Tempo“) → Handy (CSV per HSSP) bzw. Satisfyer. Die Heatmap zeigt toolActions().

Vibration

scriptSource() liefert { actions, ms } aus Steuern oder Video. targetLevel() rechnet je nach Übersetzung eine Stärke 0–1, eine 60-ms-Schleife glättet und sendet nur bei Änderung. Not-Aus und Pause setzen sofort 0.

Handy-Sync

doSync() lädt das Script vor (handy.prepare, Upload wird gecacht) und startet mit handy.play(mediaTime()·1000 + Offset). Ereignisse am Video lösen resync() aus; alle 30 s wird still nachkorrigiert, alle 5 min die Uhr neu abgeglichen.

Einstellungen speichern

Pro Gerät in localStorage über store.get/set (Präfix hp.). Nur Patterns und Script-Baukasten liegen auf dem Server (/api/store → data/store.json).

Protokoll der Fernbedienung

Jede offene Seite verbindet sich mit GET /api/remote/events?id=…&name=…&screen=1 (Server-Sent Events). Die ID ist pro Tab fest (sessionStorage), damit ein Neuladen die Verbindung nicht verliert. Der Server speichert nichts, er reicht nur weiter.

Ereignisse vom Server

  • screens – { list: [{ id, name, state }], peers }
  • state – { id, state } eines Bildschirms
  • cmd – { from, cmd, arg } an diesen Bildschirm

Befehle (POST /api/remote/cmd)

open (Szene), play, pause, toggle, seek (Sekunden), stop (Not-Aus), fs (Vollbild), refresh (Stash-Infos neu), hello (Zustand jetzt senden).

// Zustand eines Bildschirms (POST /api/remote/state, alle 3 s und bei jeder Änderung)
{
  "src": { "kind": "stash", "id": "123", "title": "…", "interactive": true },
  "t": 760.4,            // Position in Sekunden …
  "at": 1793448541635,   // … gemessen zu dieser Serverzeit (ms)
  "playing": true, "paused": false, "duration": 1865,
  "handy": true,         // Bildschirm steuert die Handy selbst
  "info": { "rating100": 80, "favorite": true, "oCounter": 2 },
  "markers": [{ "seconds": 312, "title": "Lieblingsstelle 5:12" }],
  "error": ""            // "autoplay" = Browser wartet auf eine Berührung
}

Die Fernbedienung rechnet t + (Serverzeit jetzt − at) / 1000. Die Abweichung zur Serveruhr misst jede Seite mit fünf Anfragen an /api/remote/time (die schnellste zählt) und wiederholt das jede Minute. Kommt 8 s kein Zustand, gilt der Bildschirm als angehalten.

Arbeiten am Code

Lokal starten

MEDIA_DIR=./testmedia DATA_DIR=./data \
STASH_URL=http://stash:9999 \
node server.js
# → http://localhost:8080

Ohne Stash läuft alles mit den Ordnern. Web Bluetooth geht auf localhost auch ohne HTTPS.

Ablauf einer Version

  1. Ändern, dann node --check für alle JS-Dateien.
  2. Im Browser testen (Testvideo + Funscript, Stash ggf. nachbauen).
  3. VERSION, CHANGELOG.md, bei größeren Versionen RELEASE-NOTES-x.y.z.md – jeweils „was & warum“.
  4. Commit, Tag vX.Y.Z, ZIP für Docker per git archive.

Sprache

Oberfläche, Kommentare und Doku auf Deutsch; Kommentare erklären das Warum.

Keine Abhängigkeiten

Nur Node-Standardbibliothek und Browser-APIs. Kein Build, kein Bundler.

Sicherheit zuerst

Alles, was Geräte bewegt, muss über emergencyStop() stoppbar sein und bei fehlender Verbindung anhalten.
